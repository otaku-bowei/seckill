# 分布式架构下的锁问题

## 问题：多个后端实例都能获取锁吗？

```
┌───────────────────────────────────────────────────────────────┐
│  分布式架构                                              │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐              │
│  │ 服务A   │    │ 服务B   │    │ 服务C   │   3个实例    │
│  │Redisson │    │Redisson │    │Redisson │              │
│  └────┬────┘    └────┬────┘    └────┬────┘              │
│       │               │               │                     │
│       └───────────────┼───────────────┘                     │
│                       │                                   │
│              ┌────────▼────────┐                          │
│              │   Redis集群    │  ← 共享的锁管理者         │
│              │               │                           │
│              │ lock:sku:1    │  ← 实际的锁存这里        │
│              │ (SET NX)       │                           │
│              └───────────────┘                          │
└───────────────────────────────────────────────────────────────┘

流程：
  服务A: tryLock() → Redis: OK ← 获取锁成功 ✓
  服务B: tryLock() → Redis: 失败 ← 等待A释放
  服务C: tryLock() → Redis: 失败 ← 等待A释放
```

## 关键点

```
┌─────────────────────────────────────────────────────────────┐
│  结论：Redisson的锁是被所有后端实例共享的                  │
├─────────────────────────────────────────────────────────────┤
│                                                       │
│  - 每个后端实例都有Redisson客户端                        │
│  - 但它们都连接同一个Redis集群                         │
│  - 锁资源存在Redis里，不是各实例的内存里                 │
│  - 谁先获取锁是由Redis决定的，不是有实例决定的         │
│                                                       │
│  ═══════════════════════════════════════               │
│                                                       │
│  所以：                                                │
│    ✓ 多个实例可以安全使用Redisson锁                    │
│    ✓ Redis是协调中心，保证互斥                         │
│                                                       │
└─────────────────────────────────────────────────────────────┘
```

## 对比Lua方案

| | Lua | Redisson |
|--|-----|--------|
| 协调位置 | Redis端（Lua脚本强制串行） | Redis端（SET NX锁） |
| 多个实例 | 每个实例都能发Lua脚本 | 每个实例都能尝试获取锁 |
| 安全性 | ✓ ��全 | ✓ 安全 |
| 性能 | ✓✓ 更高 | ✓ 略低 |

**结论：两者都可以在分布式架构下安全工作，Redis是共享的协调中心。**
