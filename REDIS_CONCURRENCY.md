# Redis 并发问题详解

## 1. 单线程概念

```
┌───────────────────────────────────────────────────────────┐
│  单线程是指：每个 Node 内部是单线程                    │
│                                                           │
│  Redis Cluster = 多个 Redis 进程，每个都是单线程          │
│                                                           │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐                │
│  │ Node A  │    │ Node B  │    │ Node C  │                │
│  │ 单线程  │    │ 单线程  │    │ 单线程  │                │
│  │         │    │         │    │         │                │
│  │ Event   │    │ Event   │    │ Event   │                │
│  │ Loop    │    │ Loop    │    │ Loop    │                │
│  └─────────┘    └─────────┘    └─────────┘                │
│                                                           │
│  每个 Node 独立处理自己的请求，互不影响                   │
└───────────────────────────────────────────────────────────┘
```

## 2. 关键问题：谁先查到数据？

```
场景：100个用户同时抢 skuId=1

假设 Cluster 中：
  节点A (master) 持有 sku:stock:1 这个 key

100个请求同时到达不同 Node：
  ┌────────────────────────────────────────────┐
  │  请求1 → Node A → GET sku:stock:1 = 10    │
  │  请求2 → Node B → 重定向到 Node A           │
  │  请求3 → Node C → 重定向到 Node A          │
  │  ...                                     │
  │  请求100 → Node B → 重定向到 Node A         │
  └────────────────────────────────────────────┘
                        │
                        ▼
              都是查 Node A 数据，谁先读到？
              Node A 单线程，串行处理
```

## 3. 实际处理流程

```
┌───────────────────────────────────────────────────────────┐
│                  Redis Cluster 路由                     │
├───────────────────────────────────────────────────────────┤
│                                                       │
│  客户端 → 计算slot → 直接路由到对应Node                  │
│                                                       │
│  "sku:stock:1" → hash(key) % 16384 = 1234              │
│  1234 落在 Node B                                      │
│  直接去Node B请求，无需重定向                           │
│                                                       │
│  ═══════════════════════════════                     │
│                                                       │
│  Node B 内部单线程处理请求：                          │
│  - 请求1: GET → 返回 10                               │
│  请求1完成后才处理��求2                               │
│  - 请求2: GET → 返回 10（还是10，因为还没扣减）        │
│  - 请求3: GET → 返回 10...                            │
│                                                       │
│  ═══════════════════════════════                     │
│                                                       │
│  真正并发问题：                                       │
│  不是不同Node之间的并发                               │
│  而是同一时刻多个请求同时到同一Node                   │
│  Node 单线程串行处理，但每个请求都拿到旧值              │
│                                                       │
└───────────────────────────────────────────────────────────┘
```

## 4. 结论

| 问题 | 答案 |
|------|------|
| 单线程是每个Node单线程，整个集群不是单线程 | ✓ |
| 同一个SKU的不同请求会落到不同节点吗？ | 不会，slot计算相同会落到同一Node |
| 不同Node查询同一key会有并发问题吗？ | **不会**，数据通过slot固定路由到同一Node |
| 并发问题出在哪？ | **同一Node内部的多个请求**，虽然串行但都拿到旧值 |

### 所以关键点：

```
┌─────────────────────────────────────────────────────────┐
│  Redis Cluster 本身不会出并发问题                      │
│  因为每个key固定路由到同一个Node                       │
│                                                       │
│  但业务层面的问题：                                 │
│  - 请求1: GET stock=10                             │
│  - 请求2: GET stock=10（此时还没扣减）               │
│  - 请求3: GET stock=10                              │
│  - ...                                           │
│  - 然后所有请求都去 DECR                           │
│                                                       │
│  ══════════════════════════════                 │
│                                                       │
│  解决方案：                                        │
│  把 CHECK库存 + DECR库存 合并成原子操作           │
│  Lua脚本或 WATCH+MULTI 事务                        │
└─────────────────────────────────────────────────────────┘
```

**所以你的理解基本对了，只是Redis Cluster本身数据是通的（通过slot路由），问题在于并发请求同时读到旧值然后都去扣减，导致超卖。**
